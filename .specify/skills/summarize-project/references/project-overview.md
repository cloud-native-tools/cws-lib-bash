# 层参考：项目概览 —— 项目的目标是什么

对应报告 `## 项目概览` 节。面向外部读者回答第一层问题：**这个项目为什么存在？目标是什么？边界在哪里？** 工作流主框架见 [../SKILL.md](../SKILL.md)；跨层公共约定（报告骨架、刷新规则、一致性清单）见 [visualization-playbook.md](visualization-playbook.md)。

## 呈现要素

| 要素 | 内容 | 形态 |
|------|------|------|
| 背景 | 项目为什么启动、解决什么问题 | 1–2 段纯 Markdown 叙述 |
| 目标 | 项目要达成的业务成果，1–3 条 | 条目列表，每条注明出处 |
| 范围 | 做什么（in scope）/ 不做什么（out of scope） | 两组条目列表 |

## 取材优先级

| 项目类型 | 信息源（按优先级） |
|----------|-------------------|
| SpecKit 项目 | `memory/constitution.md`（使命与原则）→ `specs/<key>/requirements.md` 的目标/背景节 → `memory/features.md` 顶层描述 → README |
| 非 SpecKit 项目 | README → docs/ 项目文档 → 外部需求/立项文档 → 用户描述 |

## 提炼规则

- **业务语言**：目标写成业务成果（"让 X 用户能够 Y"），不写内部代号与技术实现细节。
- **目标 ≠ 范围**：目标是要达成的成果，范围是工作边界；两者分开呈现，不混写。
- **可溯源**：每条目标必须能指回具体材料（文件+章节）；材料没有明说目标时，宁可发起澄清或显式标注"推断自 <出处>"，绝不编造。
- **读者一分钟读完**：全节控制在一屏内；背景不超过两段，目标不超过 3 条。
- **口径对齐**：本节提到的阶段/特性名称与后续各层（需求与特性、功能分解）逐字一致。

## 落笔检查

- [ ] 背景、目标、范围三要素齐全（材料缺失的要素显式说明缺失）
- [ ] 每条目标有出处；推断性内容已显式标注
- [ ] 无内部黑话；外部读者不读代码也能看懂
- [ ] 篇幅一屏内
