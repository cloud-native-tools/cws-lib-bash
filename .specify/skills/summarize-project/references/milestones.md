# 层参考：项目里程碑 —— 里程碑是什么、完成了哪些

对应报告 `## 项目里程碑` 节。面向外部读者回答两个问题：**项目的里程碑是什么？当前完成了哪些里程碑？** 工作流主框架见 [../SKILL.md](../SKILL.md)；跨层公共约定见 [visualization-playbook.md](visualization-playbook.md)。

## 呈现要素

- **里程碑视图**：仅含里程碑条目的紧凑 `@startgantt` 图（PlantUML 源码嵌入）——每个里程碑用 `[名称] happens <日期>` 或 `[名称] happens at [工作项]'s end` 声明为零工期菱形节点。
- **里程碑跟踪表**：列固定为「里程碑 | 锚定（日期或关联工作项） | 状态（achieved / pending / at-risk）」；表格行与视图中的 `happens` 条目一一对应、同名同锚定。
- **达成叙述**：一句显式结论回答"完成了哪些"——如"6 个里程碑已达成 2 个（M1 需求冻结、M2 首版发布），其余 pending"。

## 里程碑识别

- **候选类型**：关键评审、版本发布、验收节点、阶段完成点。
- **SpecKit 取材**：git 标签、`features.md` 状态跃迁（如某批特性全部 Implemented）、规格完成节点（spec 的 verification 通过）。
- **非 SpecKit 回退**：git 标签、发布记录、路线图文档中的节点。
- 材料中没有的里程碑不得虚构；用户口述的里程碑注明"来源：用户描述"。

## 锚定与状态规则

- **锚定二选一**：绝对日期，或关联功能分解树中某工作项的结束点（`happens at [...]'s end`）；工作项名称与分解树逐字一致。
- **achieved**：须有材料依据（标签已打、版本已发布、验收记录存在），并在表格或叙述中给出依据。
- **pending**：默认状态，尚未到达且无风险信号。
- **at-risk**：判定须有材料依据（如所锚定工作项已延期、依赖项落后）；无依据不标注。

## 与任务进展层的一致性

- 里程碑视图中的全部 `happens` 条目**逐条复制**进任务进展层的甘特图（同名、同锚定、同状态）——一致性在生成时保证，而非留待落盘前自检兜底。
- 跟踪表、里程碑视图、进展甘特图三处的里程碑同名、同锚定、同状态。

## 落笔检查

- [ ] 每个里程碑可溯源；achieved 有依据；at-risk 有依据
- [ ] 视图 `happens` 条目与跟踪表逐行对应
- [ ] 达成叙述给出 N/M 结论
- [ ] 全部条目已复制进进展甘特图
