# 层参考：功能分解 —— 项目包含哪些任务

对应报告 `## 功能分解` 节。面向外部读者回答：**项目的工作被分解为哪些阶段与任务？** 本层产出的**单一功能分解树**是里程碑层与任务进展层的唯一数据源。工作流主框架见 [../SKILL.md](../SKILL.md)；跨层公共约定见 [visualization-playbook.md](visualization-playbook.md)。

## 呈现要素

- **WBS 工作分解图**：`@startwbs` 渲染分解树（PlantUML 源码嵌入），遵循 draw-plantuml 的 `references/howto/13-wbs-diagram.md`。
- **配套说明**：一段简要文字说明树的层级含义与读图要点。

## 分解深度规则

- **默认三级**：阶段（phase）→ 任务（task）→ 子任务（sub-task，可选）。至少覆盖 阶段 → 任务 两级。
- **叶子即工作包**：叶子节点是可分配、可估算的最小单位；粒度以"一句话能说清交付物"为准。
- **命名规范**：业务语言动词短语（如"完成镜像构建流水线"），不用内部代号；同一工作项在 WBS、甘特图、里程碑视图、叙述中**逐字一致**。
- **数量控制**：单图节点 ≤15 时一图呈现；超出按 playbook「大项目图集拆分」节拆分为概览图 + 阶段下钻子图。

## 取材优先级

| 项目类型 | 信息源（按优先级） |
|----------|-------------------|
| SpecKit 项目 | `specs/<key>/plan.md` 的模块划分（适合作为阶段层）→ `tasks.md` 的任务分组 Phase/Story（适合作为任务层）→ 模块目录结构 |
| 非 SpecKit 项目 | 代码目录结构 → 架构文档 → 任务清单/看板导出 |

- **多 spec 归并**：多个 spec 并存时按特性或主题归并为顶层分支，避免每个 spec 平铺成一级。

## 单一数据源约定

分解树在进入绘图前先在上下文中定稿（命名、层级、归属）；之后：

- 里程碑层的每个里程碑锚定到本树中的工作项或绝对日期；
- 任务进展层的甘特条目与本树带时间信息的叶子工作项一一对应；
- 三处命名逐字一致，不允许任何图中出现树里不存在的孤儿条目。

## 落笔检查

- [ ] 至少两级分解，叶子可分配可估算
- [ ] 节点命名业务语言、跨图逐字一致
- [ ] 单图节点 ≤15，超出已拆分图集
- [ ] 每个分支可溯源到材料
