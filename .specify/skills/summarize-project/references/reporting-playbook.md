# 项目总结操作手册 (Reporting Playbook)

`summarize-project` 技能的**跨层公共约定**：报告结构、刷新规则、图集拆分、三图一致性清单、范围与粒度控制、落盘检查单、外部文档取材。各呈现层面的细则已分解到独立层参考文档（见下方索引）；工作流主框架见 [../SKILL.md](../SKILL.md)；图表语法与渲染以 draw-plantuml 技能的操作指南为准。

## 0. 层参考文档索引（一层一文档）

面向外部用户全面展示项目现状时，报告从五个层面逐层呈现；每个层面对应 `references/` 下一份层参考文档：

| 外部读者的问题 | 呈现层面 / 报告章节 | 层参考文档 |
|----------------|---------------------|------------|
| 项目的目标是什么？ | `## 项目概览` | [project-overview.md](project-overview.md) |
| 项目要交付哪些能力？ | `## 需求与特性` | [requirements-features.md](requirements-features.md) |
| 项目包含哪些任务？ | `## 功能分解` | [work-breakdown.md](work-breakdown.md) |
| 里程碑是什么？完成了哪些里程碑？ | `## 项目里程碑` | [milestones.md](milestones.md) |
| 每个任务当前的状态？整体进度安排？ | `## 任务进展` | [task-progress.md](task-progress.md) |

各层文档统一结构：呈现要素 → 取材优先级 → 组织/推断规则 → 落笔检查。生成对应章节前先读对应层文档；本手册只保留跨层约定，不重复层内细则。

## 1. 报告结构（派生呈现物）

默认位置：SpecKit 项目 `.specify/project/summary.md`，非 SpecKit 项目 `docs/project-summary.md`（检测脚本输出 `default_report_path`，用户可覆盖）。章节骨架固定如下：

````markdown
# <项目名> 项目总结报告

## 项目概览
<背景、目标、范围 —— 提炼自事实源的纯 Markdown 文本，注明出处>

## 需求与特性
<「特性 | 来源 | 状态」清单表格>

```plantuml
@startmindmap
' 可选：特性分组概览（特性数量适合图示时）
@endmindmap
```
<本图源码的内联 SVG 渲染结果（禁止路径引用图片文件）>

## 功能分解

```plantuml
@startwbs
' 单一分解树：阶段 → 任务 →（可选）子任务
@endwbs
```
<本图源码的内联 SVG 渲染结果（禁止路径引用图片文件）>

## 项目里程碑
<「里程碑 | 锚定 | 状态」跟踪表格>

```plantuml
@startgantt
' 仅含里程碑条目的紧凑视图：[名称] happens <日期> / happens at [工作项]'s end
@endgantt
```
<本图源码的内联 SVG 渲染结果（禁止路径引用图片文件）>

## 任务进展

```plantuml
@startgantt
' 三态进度 + 百分比 + 当前日期参照线 + 里程碑菱形 + 依赖
@endgantt
```
<本图源码的内联 SVG 渲染结果（禁止路径引用图片文件）>

## 附注
<用户手工补充区；技能刷新报告时原样保留本节，无此节则不创建>

## 元信息
- 生成日期：YYYY-MM-DD
- 信息源：<本次实际读取的事实源清单（工件路径 / 外部文档 / git）>
- 估计假设：<逐条显式标注，无则写「无」>
````

- **图表即文本，交付自包含**：PlantUML 源码块是权威形态、永不删除；每张图必须渲染并将 **SVG 渲染结果内联嵌入**源码块之后——报告为单文件自包含文档，禁止相对/绝对路径图片引用与外链图片 URL，读者无需任何本地或本项目依赖即可完整阅读。
- **派生定位**：除 `## 附注` 外全部章节视为可再生的派生内容；报告不承载人工维护的事实，事实修正应回到信息源材料中进行。

## 2. 刷新规则（重复运行）

- **整体重生成**：每次运行重新读取信息源并重生成报告正文（概览、特性清单、图表、表格），保证呈现与事实源同步；不存在"增量维护事实"的概念。
- **附注保留**：既有报告中的 `## 附注` 节逐字节保留并放回固定位置；用户写在其他章节的手工内容不保留（可在刷新前提示一次）。
- **变更留痕**：每次运行刷新 `## 元信息`（生成日期 + 信息源清单 + 四道门禁确认状态）；里程碑状态以事实源为准重新判定。
- **确认沿用**：刷新运行仍走四道门禁；与既有报告逐字一致的门禁章节可合并为一次「全部沿用」确认，有变化的章节逐层确认（见 [../SKILL.md](../SKILL.md) Step 4「刷新运行的批量确认」）。
- **只读红线**：对 `.specify/`、外部文档、代码与 git 仓库只读取，不写入、不整理、不"修复"。

## 3. 大项目图集拆分

- **触发**：WBS 节点 >15，或甘特条目 >20，或单图宽高比严重失衡。
- **结构**：1 张概览图（只到阶段层）+ 每阶段 1 张下钻子图；概览图标注「▶ 见 图N」交叉引用。每张子图是报告内独立的 PlantUML 源码块。
- **一致性**：图集内命名、配色、编号、字号跨图一致；每张子图自足（不读其他图也能看懂该阶段）。
- 拆分技术（方向、配色、图注外置）遵循 draw-plantuml 的图集与大图指南。

## 4. 三图一致性自检清单（落盘前必过）

- [ ] 每个带时间信息的 WBS 叶子工作项在进展甘特图中有且仅有一个同名条目
- [ ] 甘特图中没有 WBS 里不存在的孤儿条目
- [ ] 里程碑视图、里程碑跟踪表、进展甘特图三处里程碑同名、同锚定、同状态
- [ ] 里程碑视图的全部 `happens` 条目已逐条复制进进展甘特图（生成时保证，非事后修补）
- [ ] 进展甘特图的 `today` 以 `today is N days after start` 相对项目起点显式定位（不依赖渲染环境时钟）
- [ ] 三态（completed / in-progress / not-started）在图与叙述中口径一致
- [ ] 特性清单表格的每一行都有来源出处，与 `## 需求与特性` 叙述一致
- [ ] 所有估计性时间/状态都已在 `## 元信息` 假设区显式标注
- [ ] 每个 PlantUML 源码块都通过 draw-plantuml 渲染校验
- [ ] 每个 PlantUML 源码块之后均紧跟其内联 SVG 渲染结果（无未渲染的裸源码块）
- [ ] 报告内不存在相对路径/绝对路径图片引用与外链图片 URL（单文件自包含，可独立转移分发）

**标准渲染校验命令**（在报告所在目录执行；按源码块顺序命名，避免每次手写提取逻辑）：

```bash
python3 - <<'EOF'
import re, pathlib
text = pathlib.Path("summary.md").read_text()
blocks = re.findall(r"```plantuml\n(.*?)```", text, re.S)
names = ["features", "wbs", "milestones", "gantt"]  # 与报告中源码块顺序一致；图集拆分或省略可选图时按需调整
for name, src in zip(names, blocks):
    pathlib.Path(f"{name}.puml").write_text(src)
    print(name, "->", len(src.splitlines()), "lines")
EOF
# 逐个渲染校验（render-plantuml.sh 路径以 draw-plantuml 技能安装位置为准）
for f in features wbs milestones gantt; do <draw-plantuml>/scripts/render-plantuml.sh $f.puml . $f; done
```

## 5. 呈现范围与受众粒度

- **周期限定**：用户给出呈现周期（如"本季度"）时，甘特时间轴与叙述只覆盖该范围；范围外工作省略，或在图中以弱化样式呈现并注明。
- **粒度限定**：高管受众默认只展开到阶段层（任务层以汇总行表示）；技术受众展开到任务/子任务层。
- 无论粒度如何，阶段级结构必须完整呈现，三图一致性清单仍然全量适用。

## 6. 报告落盘检查单

- [ ] 五个呈现章节齐全：项目概览 / 需求与特性 / 功能分解 / 项目里程碑 / 任务进展
- [ ] 四道门禁确认状态：项目概览 / 项目里程碑 / 功能分解（WBS 渲染确认）/ 任务进展（甘特渲染确认）均已确认，或 `## 元信息` 已标注「未经交互确认」/ 部分跳过
- [ ] 每个章节已按对应层参考文档的「落笔检查」过检
- [ ] 每图配一段简要说明（图讲了什么、读者应关注什么）
- [ ] 元信息齐全：生成日期、信息源清单、估计假设（assumptions）
- [ ] 既有 `## 附注` 节（若有）原样保留
- [ ] PlantUML 源码嵌入报告且全部通过渲染校验；每张图的 SVG 渲染结果已内联嵌入源码块之后，源码保留
- [ ] 输出位置与检测脚本给出的默认路径一致（或用户已指定）；报告单文件自包含——无相对/绝对路径图片引用、无外链图片 URL，移动或外发后仍可完整阅读
- [ ] 未对任何信息源工件产生写入

## 7. 外部文档取材

- **可接受的来源**：Markdown/Word/PDF 需求文档、任务清单、看板导出、会议纪要、路线图、发布说明、issue/PR 导出；office 文档的读取可借助 document-utils 技能。
- **取材规则**：逐条记录条目来自哪个文件哪个章节；文档间冲突时以更新日期的材料为准并在叙述中注明冲突；扫描件/图片类材料无法可靠读取时显式说明，不臆造内容。
- **外部系统**：用户提供的是导出文件时正常取材；本技能不主动接入 Jira/CI/CD 等外部系统的在线 API。
