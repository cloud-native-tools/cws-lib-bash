# 层参考：任务进展与整体进度安排 —— 每个任务什么状态、整体怎么排期

对应报告 `## 任务进展` 节。面向外部读者回答两个问题：**每个任务当前的状态是什么？项目的整体进度安排是怎样的？** 工作流主框架见 [../SKILL.md](../SKILL.md)；跨层公共约定见 [visualization-playbook.md](visualization-playbook.md)。

## 呈现要素

- **进展甘特图**：`@startgantt`（PlantUML 源码嵌入），遵循 draw-plantuml 的 `references/howto/14-gantt-diagram.md`，包含三态进度、完成百分比、当前日期参照线、里程碑菱形（逐条复制自里程碑层）、依赖关系。
- **整体进度叙述**：一段面向外部读者的排期总结——各阶段起止区间、当前所处阶段、整体完成度、剩余工作展望；这是"项目整体进度安排"的文字答案，与甘特图互为印证。

## 进度状态推断

| 材料信号 | 推断状态 | 备注 |
|----------|----------|------|
| 任务清单勾选完成 / 规格状态 Implemented / 已发布 | completed | 百分比 100 |
| 进行中分支、部分完成清单、规格状态 Planned/进行中 | in-progress | 必须给出百分比及依据 |
| 未启动、无痕迹 | not-started | 百分比 0 |

- **SpecKit 状态口径**：`tasks.md` 中 `[x]` 为 completed、`[ ]` 且所属 spec 进行中为 in-progress/not-started（按 spec 整体状态判定）。
- 推断依据写入报告叙述或图注；无依据的状态不标注。
- **退化情形**：项目未开始（全部 not-started）或全部完成（全部 completed）时图表仍须正常渲染，叙述中显式说明整体状态。

## 当前日期参照线

- 项目进行期（同时存在 completed 与 not-started/in-progress）时，甘特图必须标出当前日期参照线。
- `today` **必须**以 `today is N days after start` 相对项目起点显式定位——不得依赖渲染环境时钟。

## 时间信息的估计默认与假设标注

材料缺少日期/工期时的处理顺序：

1. **有锚点用锚点**：git 标签、发布日期、规格创建日期、迭代周期都可作为锚点。
2. **相对排期**：只知先后顺序时，用相对依赖排期（B 在 A 结束后开始），不给绝对日期。
3. **必须估计时**：按同类任务的常规工期给默认值，并在报告 `## 元信息` 中**逐条显式标注**为估计假设（assumptions），格式：「假设：<工作项> 工期估计为 N 天（材料未提供）」。
4. **猜测会误导时**：转为最多一轮澄清提问（≤4 问），不静默落笔。

## 依赖关系

- 工作项间先后依赖按材料呈现；无依据时不虚构依赖。

## 落笔检查

- [ ] 甘特条目与功能分解树带时间信息的叶子一一对应，无孤儿条目
- [ ] in-progress 条目均有百分比及依据；三态口径与其他章节一致
- [ ] `today` 相对项目起点显式定位；进行期项目有参照线
- [ ] 里程碑条目与里程碑层同名同锚定同状态
- [ ] 估计性时间已在 `## 元信息` 逐条标注为假设
- [ ] 整体进度叙述与甘特图互相印证
