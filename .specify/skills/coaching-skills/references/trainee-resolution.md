# Trainee resolution — scan both lists, never judge by syntax

Owner of reference: `SKILL.md` § Trainee Resolution (pointer). This file carries the
scan coordinates, the aliases and the failure table; the rule itself is the body's.

## Why scanning, not syntax

A leading `/` does **not** discriminate: in this host skills are surfaced as slash
commands too (`/improve-skills`, `/coaching-skills`), and command surfaces also carry
it (`/speckit.status`). The executor kind is decided by **which list actually contains
a hit**, never by the reference's shape.

## Scan coordinates

Normalize first: strip one leading `/`; when the remainder starts with `speckit.`,
also try the remainder with that prefix removed.

| List | Canonical coordinates | Installed aliases |
|---|---|---|
| **Skill** | the `run-skills` position ladder: canonical internal → canonical external → installed internal → installed external; a hit matches the directory name or the `SKILL.md` frontmatter `name` | the same ladder's installed layers |
| **Command** | `.specify/templates/commands/<name>.md` (the command's canonical template; its body is the execution contract) | the host tool's generated per-tool command copies (regenerated by `regen-command-copies.py`, never hand-edited) |

A source hit and its installed alias are **one hit** (same executor). Only two distinct
executors carrying the same normalized name are two hits.

## Decision

| Reading | Decision |
|---|---|
| exactly one hit, skill list | executor kind `skill`; decision class `skill` (internal / external / installed) |
| exactly one hit, command list | executor kind `command`; decision class `command` |
| zero hits in both lists | fail closed naming the raw form and the searched coordinates of **both** lists |
| two hits inside the skill ladder | fail closed naming both candidate paths — never pick the nearest |
| one skill hit **and** one command hit with the same normalized name | fail closed naming both candidates: the reference is ambiguous and the user disambiguates (skill vs command surface) |
| the resolved executor is unreadable (no readable `SKILL.md`, no readable template) or its frontmatter is invalid | reject before the expectation phase, naming the path |

The recursion guard still applies: a resolution that lands on this skill fails closed
before the expectation (never write the running skill from inside its own run).

## Recording

`expectation.md` and `observation.md` carry the `executor-kind` row and the resolved
absolute path; the DispatchRecord's `mode` records the transport, not the kind.
