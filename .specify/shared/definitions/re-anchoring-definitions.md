# Re-Anchoring Definitions — 不忘初心 · 温故而知新

**Owner（唯一所有者）**: 本文件拥有「agent 如何记住并周期性地重新确认初始任务与规则」这一纪律的**概念定义**、
**重载分层**与**agent 侧义务**。可执行程序（驱动检查点五问）的 owner 是
`sdd-loop-driver/references/checkpoint-protocol.md` § Direction audit；本文件引用它，不复述其执行步骤。

## 1. 两个核心概念

> **复习的对象是规则，不是目标。** 当前正在做的事与下一步已经隐含了目标；被丢弃的规则不会在下一步里显形。
> 本项目的真实事故：`无人值守` 这条规则被忽略——包边界开始征求「要不要继续」、状态脊长期停在包 1——而工作本身仍然
> 一步一步正常推进。目标从未丢失，丢失的是规则。

### 1.1 不忘初心（Never Forget the Initial Rules and Task）

<!-- 092 handoff: D5 → 090-re-anchoring -->

- 每个 agent 在入口处 MUST 固化一份**方向锚**，它包含两部分：
  - **任务锚**：用户原始目标（逐字）、非目标、验收权威、阶段计划、裁定门；
  - **规则锚**：当前生效的**操作规则集**——封闭八项，成员与逐项释义的**唯一枚举**即本小节（§1.1）下列清单，
    任何其他位置（含本文件 §1.2、§3）只以指针抵达，不复述成员。
    1. ① 无人值守（不征求继续）；
    2. ② U4 通过即派发下一阶段；
    3. ③ 状态脊先写后动；
    4. ④ workspace guard；
    5. ⑤ fast-fail 的纠正/裁定二分；
    6. ⑥ 确认门纪律；
    7. ⑦ 预算纪律（token 与时间预算）；
    8. ⑧ 报告纪律（进度报告与回传形态）。
- 方向锚 MUST 落在可持久、可重读的载体上（驱动状态脊 / agent 的分配简报），MUST NOT 只存在于会话上下文。
- **两个词不是一件事**：**方向锚**（direction anchor）是一次派发/一轮运行内部「任务锚 + 规则锚」这两部分的合称，
  分节见上两项，它是本纪律的操作对象；**anchoring**（锚点）是项目级、跨运行留存的方向锚归档实体，见 §5。
  二者不可互相指代：说「方向锚已归档」是错的，说「anchoring 在本轮内被重读」也是错的。
- 会话被压缩、切换或重入时，agent MUST 从方向锚恢复，而不是从记忆或印象恢复。
- 任何与方向锚冲突的动作 MUST 先停下：要么是纠正（唯一读法、局部可逆），要么是裁定（回到用户或上游）。

### 1.2 温故而知新（Review the Old, Know the New）

- 「开局加载一次」不足以抵抗长会话中的漂移。每完成一个**核心步骤**（阶段 U4、包边界、检查点、子代理返回），
  agent MUST 执行一次 **compact → reload → evaluate**：
  1. **compact**：把当前状态压成一句话（已完成 / 正在做 / 下一步 / 阻塞），不携带原始长文；
  2. **reload**：重读方向锚与规则摘要（见 §2 分层）——**规则锚优先**；
  3. **evaluate**：回答五问并给出三值判定（`on-track` / `correction-applied` / `decision-needed`）。
- 五问（**规则优先**）：
  1. 本核心步骤受哪些规则约束？逐条是否仍然生效（封闭八项的成员清单唯一枚举在 §1.1，此处不重复）？
  2. 上一动作是否在这些规则下完成——没有以汇报代替执行、没有把子代理轮次上限当作交回理由？
  3. 下一步是否仍是计划/分配中命名的那一步？（目标由它隐含，不必单独追问）
  4. 状态载体是否比最后一次提交/检查点更新？
  5. 领地与工作区签名是否干净？
- 只有 `decision-needed` 可以上送；另外两值记录后继续，MUST NOT 把审计变成确认门。

## 2. 重载分层（T0 / T1 / T2）

| 层 | 何时 | 重载什么 | 成本 |
|----|------|----------|------|
| **T0** | 每个核心步骤 | 状态脊的 `driver_contract` + `direction_contract` + `next_action`；或 agent 的分配锚摘要 | 约 1 KB |
| **T1** | 阶段边界、检测到会话压缩、子代理轮次上限之后、连续两次同向漂移 | 驱动 `SKILL.md` 的 Hard Requirements 段 + checkpoint 协议；agent 的规则摘要 | 约 5 KB |
| **T2** | 仅在派发形态不清或处置卡死时 | 完整手册与相关 reference | 按需 |

MUST NOT 在每个工具调用后重载整本手册：那是仪式，会把锚淹没在噪声里。MUST NOT 只依赖会话上下文，
因为压缩会丢弃它。

## 3. agent 侧义务

- **入口**：每个 agent（含被派发的子代理）在开始前 MUST 读分配简报中的方向锚，并用一句话复述。
- **核心步骤后**：MUST 重读方向锚并记录五问判定；漂移按 fast-fail 处理（纠正就地披露，裁定上送）。
- **子代理**：派发者 MUST 在简报中携带方向锚摘要（目标、非目标、验收权威、裁定门），子代理回传 MUST 带
  一条显式异常行；沉默不被读作干净。
- **规则锚的成员是封闭集合，owner 是本文件 §1.1**（本文件唯一枚举该八项成员的位置；本节只确认集合性质与消费面规则，
  不复述成员）：成员清单、编号与逐项释义一律以 §1.1 为准。消费面（两侧宪法、两侧指令面、
  agent 定义、生成器条目）MUST 只以指针接入，MUST NOT 枚举成员；新增或删减成员只经本文件修订。
- **不新增机器**：本纪律的载体是既有的状态脊、checkpoint、分配简报与 fast-fail 通道；MUST NOT 引入
  新的评分系统、日志服务或调度器。

## 4. 与相邻纪律的边界

- **Fast Fail**：本纪律负责「发现漂移」，fast-fail 负责「漂移的纠正/裁定二分」。
- **One Source of Truth**：本文件拥有概念与重载分层；检查点的执行步骤归 checkpoint 协议；两者以路径互相引用。
- **Token Efficiency**：T0/T1/T2 是为避免「每次全量重载」而设的分层；选择哪一层由核心步骤的位置决定。
- **Anchoring archive**：归档的实体定义归 `.specify/shared/definitions/goal-definitions.md`（其自身改名的落地在 090→W1）；
  本节只拥有「anchoring 与本纪律的三条边」。

## 5. Anchoring archive

**anchoring（锚点）是项目级、跨运行留存的方向锚归档实体**，落在 `.specify/anchoring/<slug>/`。它是 §1.1 方向锚
在**运行之间**的持久形态，不是第二种锚。实体本身（构成、身份、生命周期、`active` / `achieved` / `abandoned`
取值、Targets、存储树）由 `.specify/shared/definitions/goal-definitions.md` 拥有，本节 MUST NOT 复述；标识符、文件名与
旧拼写的完整改名表同样由该页的改名裁定记录拥有，本节不列第二个副本。

**它与本纪律只有三条边，本节独自拥有这三条**：

| 边 | 内容 |
|---|---|
| 写入时机 | 一个锚点在与某次派发绑定**之前**就已存在；派发简报中的方向锚是**从 anchoring 投影出的摘要**，不是现场发明的。没有对应 anchoring 的派发，其锚来源 MUST 被点名 |
| 生命周期判据 | 方向锚的 `on-track` / `correction-applied` 是**本轮内**判定，不写回 anchoring；`achieved` / `abandoned` 是**运行之间**的归档状态，只经 `/speckit.goal` 一类的显式动作改变。MUST NOT 从一次 `on-track` 推定锚点已达成 |
| 读取面 | T2 层重载时 MAY 打开完整 anchoring；T0/T1 层 MUST NOT（§2 的分层成本对归档同样成立）。回顾面（`.specify/` 十个历史根）是否包含该树由 `.specify/shared/definitions/non-disposable-definitions.md` § Review Surface 拥有，本节不作断言 |

**不新增机器**：anchoring 复用既有的 goal 引擎与既有历史根，不引入第二套归档目录、第二份锚点注册表或第二个
`/speckit.goal` 入口。
