# Harness 三重结构定义 — markdown + yaml + script

**Owner（唯一所有者）**: 本文件 `.specify/shared/definitions/harness-triple-definitions.md` 是「harness 三重结构」这条纪律的唯一所有者，拥有六件事：**三层各自拥有什么**、**「归 yaml 的事实」判据**、**候选屏幕 S 的定义**、**范围判据与三个排除理由的语义**、**迁移时的权威取值顺序**、**非目标**。命令模板、技能、契约、测试、门户文档 MUST 以「路径 + 章节锚」引用本文件，MUST NOT 复制其判据句。

**取值域的 owner 不是本文件**: 五类 fact kind、二值完整性状态、三值排除理由、三个退出码、必填键集与门禁调用点清单全部由 `.specify/shared/declarations/contract.yaml` 拥有。本文件描述**它们是什么意思、什么时候用哪一条**，MUST NOT 再列一份取值；任一取值问题的抵达方式是 `<path>#/<key>`。

**读者**: 一位被告知「这个取值现在归声明层了」的维护者。他打开本文件要回答三个问题：我的单元在不在范围内、它欠哪一种记录、各面已经漂移时该信哪一面的值。他不需要读过本特性的规划过程。

**不在本文件**（只给指针）：

| 主题 | 所有者 |
|------|--------|
| 取值域（kind／状态／理由／退出码／必填键／调用点） | `.specify/shared/declarations/contract.yaml` |
| 声明文件的语法、目录形态、路径规范 | `.specify/shared/definitions/…` 见 `.specify/shared/declarations/contract.yaml#/yaml_subset` 所指子集；目录形态与登记见 `.specify/shared/definitions/framework-map.md` |
| 判定引擎的动作面与判定算法 | `contracts/harness-triple-check.contract.md`（`.specify/scripts/python/harness-triple-check.py`） |
| 共享读取入口的函数面与降级契约 | `contracts/shared-reader.contract.md`（`.specify/scripts/python/declaration_reader.py`） |
| 批次名单与每批验收读数 | `contracts/migration-batches.contract.md` |
| 分发与镜像义务 | `contracts/distribution-and-mirror.contract.md` |

## 本文档的地位与读者

本文件回答的是**判断**，不是**取值**。四条使用规则：

1. **先看层，再看值**。任何「这条内容该放哪里」的问题由 `## 三层各自拥有什么` 回答；任何「这个取值是什么」的问题离开本文件，去 `contract.yaml`。
2. **判据句只有一份**。其他文档引用本文件的两条判据（归 yaml 的判据、范围判据）时写「路径 + 章节锚」，不重述句子。重述即第二定义点，第二定义点会各自漂移。
3. **本文件不列名单**。候选单元由屏幕在树上重算，迁移批次由迁移契约拥有，已迁事实由声明目录自己承载。本文件列举其中任何一份，都是在造第三份名册。
4. **改判据要改这里**。判据的可判定性是本特性的交付物之一；把判据写进命令模板或技能，等于让同一句话有多个版本。

**边界**: 本章不引入新的取值、不复制契约表、不给操作步骤清单。

## 三层各自拥有什么

三层不是三种格式，而是三种**职责**。同一件事只落在其中一层，其余两层只能指向它。

| 层 | 拥有 | 不拥有 |
|----|------|--------|
| markdown（载体） | 「为什么 + 怎么读」：义务、判定顺序、边界叙事、读者需要一次读完的上下文，以及指向声明层的指针 | 机器读得到的取值；任何取值表 |
| yaml（声明层） | 「机器读得到的取值」：阈值、封闭集、有序算子表、映射、记录 schema —— 一条事实一件文件 | 判据的叙述；流程步骤；任何处理状态（处置与完整性都是派生量） |
| script（引擎） | 「确定性执行与判决」：读声明层、把取值施加到判定上、给出退出码 | 取值本身的第二份副本；判据的散文解释 |

**判定顺序**（三个问题，按序回答，前一个成立即停）：

1. **谁会因为它改变结论？** 一个确定性引擎的判决随它改变 → yaml。只有人读它 → markdown。
2. **改它的时候，是否两个以上位置必须同时变？** 是且其中一方是引擎 → yaml（跨面条件）。否 → 留在原处。
3. **一个程序能否只凭文本判定它？** 能，且它落在引擎的判决路径上 → yaml；只是被人引用 → markdown。

**顺序本身就是判据**：先问「谁读」，再问「跨不跨面」，最后才问「可不可判」。反过来问会把大量说明性内容误推进声明层。

**边界**: 本章不列举任何一条具体事实、不给 facts 清单（那是声明目录的事），也不定义取值域。

## 归 yaml 的判据

> **本节的提法与被引文的关系（092 handoff: D3 — 只在此处解释一次，改提法只改这里）**：「归 yaml 的判据 = 机器消费 ∧ 跨面」这条合取命名（下称「合取命名」）是本节的唯一判据句。`requirements.md` FR-006 曾以第二套自我嵌套的提法表述同一合取（「(i) 机器消费 ∧ (ii) 跨面」被整体冠以「**机器消费 ∧ 跨面**」，使 (i) 与 (ii) 在句子读法上互为子集，按字面读只有 (ii) 可判定）——该差异即 092 语料 D3；本次收敛不改判据内容，只把 FR-006 的表述面改为引用本节。原提法全文保留在 `.specify/specs/084-harness-triple-structure/requirements.md` FR-006 正文内，作为历史引用。

一条内容归 yaml，当且仅当**两条合取**成立（(i) **机器消费**）∧（(ii) **跨面**）：

**(i) 机器消费** —— 存在至少一个确定性引擎，**必须**读取该取值才能作出判定，且**该判定结果随取值改变而改变**：读常量作比较、按封闭集拒绝或放行、按表选门、按 schema 校验。

**(ii) 跨面** —— 该事实至少跨两个面出现。面 = 引擎、markdown 载体、模板、被测试钉住的字面量。

**任一不成立即留在原处**，不需要理由、不需要记录、不需要豁免。

三条否证，用来把 (i) 与「看起来像机器消费」分开：

- **只有测试钉住它**，没有任何引擎读它作判定 → (i) 不成立。一条标签名、一段 docstring 枚举的存在，其消费者是断言本身，不是判决。
- **引擎内部常量无第二面** → (ii) 不成立。它留在引擎里，不要为了「统一」把它搬走。
- **读者独有的说明**（维度名、判据句、理由叙述）→ (i) 不成立。它们继续留在 markdown 做自己那一层的 owner。

两条常见误读，必须明确排除：

- **重复不是判据**。重复出现只是「该迁移」的**征兆**，不是理由；先按 (i)(ii) 判，再看重复与否。
- **介质不是判据**。markdown 写得多不代表它不是机器取值；yaml 写得多不代表它就是。

**边界**: 本章不重述需求编号、不列举已迁事实、不给出取值表。

## 候选屏幕 S 与流程单元

**流程单元的身份 = 它那件 markdown 载体的仓库相对路径**。没有编号、没有注册行、没有第二套命名。

**三处载体面**（只有这三处）：

- `.specify/templates/commands/*.md`
- `skills/{external,internal}/*/SKILL.md`
- `.specify/shared/workflow/*.md`

**进入候选集的条件**：载体文本中出现至少一处指向框架内确定性引擎的路径引用 —— `.specify/scripts/python/<name>.py` 形态，或 `skills/<layer>/<name>/scripts/<file>` 形态。

三条必须一起读的限定：

1. **每次运行在树上重算**。候选集 MUST NOT 由任何手写清单代替；一份手写清单会在第一次新增命令时开始腐坏，而腐坏是静默的。
2. **`.specify/shared/definitions/*.md` 不是流程单元**。它们是事实的散文 owner：它们拥有判据，不领处置。给它们发处置会把「事实归谁」与「单元在不在范围内」两件事混成一件。
3. **文本测试的保守侧是被接受的**。只在散文里提到脚本路径、实际并不调用它的载体，仍会进入候选集。这是设计选择，不是缺陷：为此发明「是否真的调用」的第二套语义判定，正是屏幕存在的意义所要避免的东西。它的处置是一条排除记录，不是一段解释。

**排除与处置的关系**：候选集给出「谁要被处置」，不给出「处置是什么」。后者见下一章。

**边界**: 本章不列候选名单（屏幕每次重算），不列候选数量（数量是读数，不是 schema），也不定义完整性状态。

## 范围判据与排除理由的语义

**范围判据 = 两条合取**（判据句的唯一位置是本节）：

**(D1) 资产面** —— 该流程单元的验收交付物包含至少一件由 `.specify/shared/guidelines/better-harness.md` § 消费者清单 点名的 harness 资产，且能指认落点。

**(D2) 机器面** —— 该单元至少有一条按 `## 归 yaml 的判据` 归属 yaml 的事实。

**D1 与 D2 任一不成立** ⇒ 该单元必须有一条排除记录。反过来说：**没有任何单元可以既不在范围里、又没有记录** —— 这正是这条纪律要消灭的静默态。

**三个排除理由的语义**（字面取值归 `contract.yaml#/exclusion_reasons`，本文件只给语义与用法）：

| 语义 | 什么时候用 | 记录里必须有的东西 |
|------|-----------|-------------------|
| 该单元没有任何被引擎判决的事实 | 载体照旧是两层，因为它本来就没有需要机器判定的取值 | 一条能解析的锚点：它的取值为什么不在引擎的判决路径上 |
| 该单元不产出 harness 资产 | 它的产物不落在消费者清单点名的任何一类里 | 一条能解析的锚点：它的产物是什么 |
| 由上级 owner 显式保留为两层 | 有一个具名 owner 主动裁定它保持原样，且该裁定写在树内 | 一条能解析的锚点：那份裁定的位置 |

**四条使用规则**：

1. **一个单元恰有一条处置**。它由一条事实声明覆盖（该声明在 `consumers` 或 `former_carriers` 里点了它的路径），或由一条排除行点名 —— 不能两者都有，也不能两者都没有。同时命中两条是 finding，不是「按文件顺序取一个」。
2. **理由取封闭三值之一**，取值不写在行里：行是 `unit` / `carrier` / `anchor` 三键，理由由文件名承载。行内再写一个理由就是同一件事的第二份副本。
3. **`carrier` 是该单元真正够得着的东西** —— 它文本里实际调用的那个确定性引擎，不是承载该事实的 markdown。写错的 `carrier` 会让排除记录读起来像豁免口袋。
4. **锚点必须能在树内解析**。解析不了的锚点不是「已不再适用」，是一个 finding；把它当过期条目清理掉，等于允许排除记录自己过期。

**边界**: 本章不复述取值域（归 `contract.yaml`），不列被排除单元名单（那是排除记录自己的内容），也不判定某个理由「是否充分」—— 那是评审的读数。

## 迁移时的权威取值顺序

各面已经漂移时，取值的顺序是 **代码 > 生成物 > 作者文档**。

三句必须一起读：

1. **取一面，并把修正写进声明的 `note`**。声明是取值的新家，`note` 是这次修正的留痕；没有留痕的「择一对齐」不可复核，等同一面被静默丢弃。
2. **声明存在 ⇒ 引擎的内联值必须删除**。留下两份是双读，双读让「改一处、双面同时生效」这个承诺失效。
3. **声明缺席 ⇒ 允许沿用内联值，但输出必须带显式标注**。兼容路径有边界：本特性关闭时，范围内的单元不得再处于未完成状态，所以这条路径不能变成永久态。

**残留字面量的读数不在这里重新发明**。它由既有的重复字面量面给出，调用形态与逐事实归因归该面自己；本文件只要求一条：**不得为此新建扫描器**，新扫描器会让同一判定有两个答案。

**批次的存在意义是独立可验收**：一批关闭时只需要它自己的读数，与后一批是否完成为两件事；把「后一批没做完」报成「前一批失败」，会让停滞的批次拖垮已经完成的批次。名单与读数归迁移契约。

**边界**: 本章不重述批次名单（归迁移契约），不给迁移步骤清单（归迁移契约的逐事实procedure），也不定义 `note` 的措辞。

## 非目标

本能力明确**不**做下列事情。每一条都配一个越界信号，使「做过了」可以被机械看见。

- **不做配置系统、不引入 YAML 库、不做运行时求值**。声明层只被确定性引擎读取，不求值、不做表达式、不做继承与覆盖层。越界信号：依赖清单变化，或声明里出现非标量、非集合的构造。
- **不建第二套门禁**。本能力挂在既有门宿主上，不新增阶段、不新增并行判定。越界信号：出现第六个门禁阶段，或既有门禁的退出码契约发生变化。
- **不从 yaml 生成 markdown**。渲染会创造第二份呈现层，让唯一事实源在一夜之间失效；方向是散文退让为指针，不是由 yaml 反向生成散文。
- **不迁读者独有的说明**。维度名、判据句、理由叙述留在 markdown。越界信号：`## 归 yaml 的判据` 的 (i) 被读成「出现过就算」。
- **不顺手重构既有内联子集解析器**。它是已登记的既有重复，本能力登记而不趁手修：拿它开刀会把一个跨面迁移扩成解析器重构。越界信号：该脚本出现在本能力的改动清单里。
- **不改既有门禁的判据与退出码契约**。只允许其取值来源改为读声明层。越界信号：既有门禁的判定内容或退出码语义发生变化。
- **不新增阶段、不新增特性状态、不改命令序列与完成哨兵**。这是载体分层，不是流程改造。
- **不为某项具体事实开豁免口袋**。一项不迁的事实必须有具名理由与树内锚点，且不改变其所在单元的处置。

编号化的非目标登记与逐条锚点归需求规格的 `## Non-Goals`；本文件给的是**这条纪律对读者承诺的边界**，不复制那份登记。

**边界**: 本章不承诺未来特性，也不把「以后可能做」写成非目标。
