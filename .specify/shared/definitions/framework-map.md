# Spec Kit Framework Map

Single source of truth for the `.specify/` layout map. Referenced from the `## Spec Kit Framework Map` summary in `.specify/instructions.md` — keep that summary a pointer; the table lives here.

This is a **map, not a manual**: it tells you *what* exists and *where* it lives; the *how* belongs to the documents each row points to. The framework state lives under `.specify/`:

| What | Where | Notes (what lives there — not how to use it) |
|------|-------|-----------------------------------------------|
| Project memory | `.specify/memory/` | constitution, features index + `features/<ID>.md`, glossary, register, `tools/` records, feedback store, `coaching/` (coaching-run products, one artifact per file under `<run-id>/`), `housekeeping/` (sdd-house-keeping run reports, one YAML per run), `migrate/receipts/` (migration run receipts, one JSON per run at `<run-id>.json`; owner: `specify migrate`), `session/` + `knowledge/` (memory-as-files), `evidence/` (evidence runs), `exec-quant/` (run measurements), `retention/` (record consume→receipt→retire summaries, receipts, plans, ledgers), `trigger/` (proactive-flow state), `sanitize/` (findings cache) |
| Long-lived runtime state | `.specify/state/` | per-entry state kept across sessions (never one shared aggregate); e.g. SDD loop-driver line spines — owner: `.specify/shared/guidelines/directory-governance.md` §5 |
| Temporary workspace | `.specify/.tmp/` | git-ignored scratch, cleaned at work-item end; e.g. `.specify/.tmp/sdd-loop/` (worktrees, cache, tmp) — owner: `.specify/shared/guidelines/temp-directory-discipline.md` |
| Goals | `.specify/anchoring/<slug>/` | goal definitions at `goal.md` plus per-goal `summary/`; the one goal archive layer (`.specify/specs/` holds no goal subdirectory); owner: `/speckit.goal` + `goal-utils.py`; concept: `definitions/goal-definitions.md` § Archive Layers |
| History knowledge base | `.specify/history/` | distilled, theme-aggregated conversation knowledge; owner: `/speckit.history` + `history-utils.py` |
| Review reports | `.specify/review/` | archived code-review reports; owner: the `code-review` skill |
| Project summary | `.specify/project/` | `summary/` delivery directory plus legacy manage-project artifacts (read-only); owner: the `summarize-project` skill |
| Study reports | `.specify/studies/` | archived `study-code` output per target (`<target>-study/`: indexable `docs/overview.md`, outlines, strip manifest, figures, self-check evidence, target commit; the stripped source copy is not archived); owner: the `study-code` skill |
| Spec archive | `.specify/archive/spec/` | archived feature specs; owner: `/speckit.sanitize`'s archive-spec disposition |
| Goal/team archive history | `.specify/archive/goal-team/` | migration receipts (`receipts/`) and archived source trees (`trees/`), archive-not-delete; never a definition read surface; owner: `/speckit.goal` `migrate-archive` (STR-003) |
| Migrate archive | `.specify/archive/migrate/` | objects archived by `specify migrate` applies — one tree per run at `<run-id>/<relative path>`, archive-not-delete; the run's receipt (`migrate/receipts/`) enumerates each entry with its recovery path; owner: `specify migrate` |
| Artifact templates | `.specify/templates/` | requirements/plan/tasks templates rendered by `/speckit.*` |
| Automation scripts | `.specify/scripts/` | bash/python engines invoked by commands and skills |
| Installed skills | `.specify/skills/` | one directory per skill (`SKILL.md` + references/ + .specify/scripts/) |
| Skills system guide | `.specify/skills.md` | how skills are discovered and created — no registry |
| Tools system guide | `.specify/tools.md` | how tools are recorded and discovered — no registry |
| Git workflow state | `.specify/workflow/git.md` | framework-level git workflow: branch-role managed block (the `.specify/workflow/` directory holds workflow state files), machine-maintained by the `git-utils` skill |
| **Agent Templates** | `.specify/agents/templates/` | capability descriptions — shipped role set installed by `specify init`; each `.agent.md` is self-contained |
| **Agent Instances** | `.specify/agents/instances/` | responsibility-bound agents authored in this project; reference a Template |
| **Agent Execution** | `.specify/agents/execution/` | dispatch `configs/` + `.specify/scripts/` (tracked); runtime `logs/` (gitignored, never committed) |
| Teams | `.specify/teams/<slug>/` | team definitions + `runs/` reports; run intermediates in git-ignored `.work/` |
| Derivations | `.specify/derive/` | one derivation archive per topic (`<topic-slug>/derive.md`) plus the project-level reasoning-move library `moves.md` (engine-written, accumulating); record semantics in `definitions/derivation-definitions.md` |
| Shared definitions & conventions | `.specify/shared/` | canonical concept docs — e.g. agent taxonomy (`definitions/agent-definitions.md`), subagent modes (`definitions/subagent-definitions.md`), tool definitions, workflow conventions; two meta-skill owners (`definitions/mechanism-policy-definitions.md`, `definitions/skill-reference-definitions.md`) |
| Super Agent role | `.specify/shared/definitions/superagent-definitions.md` | single owner of the relative superagent/subagent role model — edge predicate, role depth, super↔sub protocol, `role-transition` injection, state-sync/recovery and visualization mapping; sibling pages carry pointers only (framework source: `.specify/shared/definitions/`) |
| Declaration layer contract | `.specify/shared/declarations/contract.yaml` | value domains the declaration layer is read through — schema and subset ids, five fact kinds, two completeness states, three exclusion reasons, three exit codes, required key sets, gate call sites; the discipline itself is `definitions/harness-triple-definitions.md` (framework source: `.specify/shared/declarations/`) |
| Declaration facts | `.specify/shared/declarations/facts/` | one fact per file, one file per fact — `<fact-slug>.yaml`, the path IS the identity; no index, no manifest, no cache (framework source: `.specify/shared/declarations/facts/`) |
| Declaration exclusions | `.specify/shared/declarations/exclusions/` | one file per exclusion reason (`<reason>.yaml`), each row carrying `unit` / `carrier` / `anchor`; rows are appended, never reordered (framework source: `.specify/shared/declarations/exclusions/`) |
| Script interface contract | `.specify/shared/definitions/script-interface-definitions.md` | owner page for the rule every directly executable `*.sh` / `*.py` script obeys — candidate screen and classification, the mandatory flags and their mandatory content, the zero-side-effect boundary, the unknown-option rejection, and the `## Declared Exceptions` register; the checker `.specify/scripts/python/script-interface-check.py` and the guard `tests/contract/test_script_interface_contract.py` consume it, and the template/live constitution, instructions and generator mandate are pointers to it (framework source: `.specify/shared/definitions/`) |
| Non-Disposable definitions | `.specify/shared/definitions/non-disposable-definitions.md` | owner page for the non-disposable discipline — the eight detection classes and their readings, the four-value disposition set and the exemption expiry model, the two disposition bridge tables, the review surface (ten `.specify/` roots declared in `.specify/shared/declarations/facts/non-disposable-review-surface.yaml`), the supersede and renumber protocols, the report schema, the status-readability contradiction table and the 档 II handoff rows; the engine `.specify/scripts/python/non-disposable-check.py`, the four-stage `/speckit.history` seam and the guard `tests/contract/test_non_disposable_contract.py` consume it (framework source: `.specify/shared/definitions/`) |
| Feature specs | `.specify/specs/<ID>-<slug>/` | requirements / plan / tasks / verification per feature; a split parent MAY hold `slices/<slice-dir>/` — archived split-slice trees kept as data inside the parent spec (never a spec candidate; move and record owned by `/speckit.seal`'s `archive-apply` plus the parent's `archive-manifest.json`); no goal/team subdirectory — both definition kinds live in the two archive layers above |
| Canonical AI instructions | `.specify/instructions.md` | single source of truth for project-level AI instructions; per-tool files are symlinks (see `workflow/symlink-model.md`) |
| [Other project-specific location] | [Path] | [What lives there] |

> Agent layer taxonomy (Template → Instance → Execution) is defined once in `.specify/shared/definitions/agent-definitions.md` — consult it before creating/refining/running agents.

> Self-Improvement terminology is defined once in `.specify/shared/definitions/self-improvement-definitions.md`; policy, reusable structure, and execution order live respectively under `guidelines/`, `patterns/`, and `workflow/`.
