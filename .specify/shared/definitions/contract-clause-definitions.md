# Contract Clause Definitions — 契约条款语法的唯一 owner

**本文档是契约条款语法(contract clause syntax)的唯一真源(owner)。** 它拥有并且只拥有以下内容:条款的**形态集**及其判据正则、一条条款的**正文边界**、条款对需求/成功判据的**引用组**规则、新契约的**规范形态**、以及**不可解析文件的处置形态**。

任何检查器、核算脚本、模板或规格在判断「一份契约里有哪些条款」「某条条款的正文到哪里为止」「某条条款引用了哪条 FR」时,MUST 以本文档为准,MUST NOT 各自另立一套语法。逐形态的**计数**不由本文档拥有——其唯一拥有者是对应 spec 的 `notes/clause-form-census.md`(该量随契约增删而变,本文档不复写任何数字)。

用户可见输出的行话与上下文纪律见 `.specify/shared/guidelines/user-facing-comprehension.md`(canonical 指针;本文档不复写其界面类表)。

---

## 1. 什么是一条条款

一条**条款 (clause)** 是一份契约文档里可被独立判定、独立引用的最小规范单元。它由一个 **id** 标识,形态为 `C-<数字>`,可带一级小数后缀(如 `C-3.4`)。id 在同一份契约内 MUST 唯一;是否要求连续由各契约自己的检查器决定,不由本语法规定。

**最小可解析子集**:一份契约只要满足「每个条款有一个可被下述某一形态的判据正则命中的 id 标记」,即视为可解析。不满足者按 § 5 处置,不得被静默算作 0 条款已覆盖。

## 2. 形态集(六种)

| 形态 | 判据(正则) | 适用 |
|---|---|---|
| `md-bold-closed` | `\*\*C-\d+(?:\.\d+)*\*\*` | Markdown,**规范形态** |
| `md-bold-paren` | `\*\*C-\d+` 命中,而闭合形 `\*\*C-\d+(?:\.\d+)*\*\*` 不命中 | Markdown,遗留 |
| `md-heading` | `^#{1,6}\s+C-\d+` | Markdown,遗留 |
| `yaml-openapi` | 文件含 `openapi:` 且含 `paths:`;条款 = `paths:` 下的 HTTP 方法键(`get`/`post`/`put`/`delete`/`patch`/`head`/`options`) | YAML |
| `yaml-assertions` | `^\s+- id:` | YAML,遗留 |
| `md-none` | 以上 `.md` 判据全部不命中 | Markdown,无可辨条款 |

**标记行 MAY 带列表前缀**(`- ` / `* ` / `+ `):形态判据与块边界都 MUST 容忍该前缀。这不是宽容,而是实测事实——遗留形态 `md-bold-paren` 的真实样本(`031-task-complexity-rubric` 的 rubric 契约)全部 10 条都写作 `- **C-N (标签)**:`,行首锚定而不允许前缀的抽取器会对它返回 0 条,把一份有 10 条条款的契约静默算成空。

**标记也 MAY 是表格首格**:把条款声明在 Markdown 表格**首格**的写法(`| **C-N** | 规则 | … |`)是 `md-bold-closed` 的一个变体,不是第七种形态——实测语料里有 5 份契约这么写。判定规则:**只有首格**的 id 是声明;出现在其它格里的 id 是**对别份契约条款的交叉引用**,MUST NOT 计入本文件的条款全集(实测有一处这样的引用,把它算成条款会让全仓条款总数多 1)。表格行条款的正文边界就是**该行本身**,它不吞并下一行。

**四条 `.md` 判据互斥**:实测同一文件同时命中两种 `.md` 形态的数量为 0,故一份 `.md` 契约恰属一类。`md-none` 是兜底类,不是「未检查」。

**OpenAPI 的条款 id 是方法键,不是一个字面键名**:MUST NOT 以文件内是否存在字面 `operations:` 键作为探测条件(实测该键在 OpenAPI 形契约中出现 0 次)。

**该方法键在文件内 MAY 不唯一**(2026-10-04 由覆盖核算实跑测得,登记为 `053-machine-decidable-artifacts/research.md` **A-8**,本文档只记事实、不在此改语法):一个文件可以在多个 path 下声明同一个方法,故 `<契约>#<方法键>` 不足以指认单个 operation。实测全仓有 **8** 份 OpenAPI 形契约存在重复方法键,抽出 id 合计与按 `<spec>/<契约>#<条款 id>` 去重后的名字数相差 **24**。因此任何以**名字集**做集合运算的消费方(覆盖核算、基线冻结、`[green:]` 认领)MUST 同时报告 id 数与去重后的名字数,并在二者不等时说明成因;MUST NOT 只印去重后的数,那会让分母静默变小——即「空因为盲」下沉到条款标识这一层。是否把该形态的 id 限定为 `<path>.<method>` 属**语法变更**,由本文档的后续修订决定,A-8 列了两个读法及其代价。

**文件扩展名不是判据**:一份命名为 `*.openapi.yaml` 的文件可能实际是 `yaml-assertions` 形。形态 MUST 由内容判定,MUST NOT 由扩展名判定。

## 3. 规范形态与遗留形态

- **规范形态 (canonical)**:`md-bold-closed`,即条款标记以行首裸粗体 `**C-N**` 出现。**新建契约 MUST 只用这一种形态**;它也是唯一保证「一行一条款、标记行即条款起点」的形态,故机器抽取无需猜测正文范围。
- **遗留形态 (legacy)**:上表其余五种。它们 MUST 被**只读识别**(能抽出 id、能判定可解析性),但 MUST NOT 被要求迁移,也 MUST NOT 因为不是规范形态而被判为不合规。识别遗留形态的目的只有一个:让核算的分母是真实的,而不是只覆盖新写法。

## 4. 条款正文边界与引用组

抽取一条条款时,以下三条规则缺一不可;缺任何一条,同一份语料会得出多个都能自圆其说的计数。

1. **块边界**:一条条款的正文自其 `**C-N**` 标记行起,至**下一个条款标记行**或**下一个章节标题行**(`^#{1,6}\s`)为止,以先到者为准。章节标题不属于任何条款块——标题里出现的需求编号不构成对该条款的引用。围栏代码块内的行不计入正文。
2. **引用组 (citation group)**:一条条款对 FR/SC 的**唯一**引用位置,是其块内**最后一个含 `FR-`/`SC-` 编号的括号组**。组外的同形字样一律按「提及 (mention)」处理,不构成引用——提及与引用的区分是既有需求纪律,本语法只负责把它落到条款粒度上。括号组 MUST 容忍一层嵌套(编号可带子项后缀,如 `(FR-018(a))`),MUST 支持区间写法 `FR-a…FR-b` 的展开。
   括号组的定界字符集是开组 `(` 或 `（`、对应闭组 `)` 或 `）`;嵌套 MUST 同宽度匹配(开组与闭组恰为同宽度,既有的一层嵌套语义不变)。跨宽度配对(半角开、全角闭,或反之)或不配对的定界符是**畸形组 (malformed group)**:检查器 MUST 将其作为独立结果报告,MUST NOT silently count it as a citation or a mention(不得静默计为引用或提及)。
3. **行内代码跨度**:判定引用前先按 CommonMark 规则剥离行内代码跨度——一段代码跨度以 N 个反引号开启、在下一处**恰为 N 个**反引号处闭合;未闭合的反引号串按字面处理。被反引号包裹的编号示例是提及,不是引用。

**为什么边界必须写下来**:不声明边界时,「条款引用了哪条 FR」取决于抽取器按行读还是按块读,同一份语料可得出相差数条的两个总数,而两者都自称实测。声明边界后,总数是规则的产物,不是读法的产物。

## 5. 不可解析与解析存疑的处置

- 一份文件若可被读取但按上述形态抽不出任何条款(`md-none`),MUST 被**逐个点名**并计入一个非零伴生量,MUST NOT 静默算作「0 条款、已覆盖」。
- 任何**解析存疑**的 YAML(流式语法、锚点、多文档、非预期缩进)MUST 回退到点名跳过,MUST NOT 猜测其条款集。猜测出来的 0 与真实的 0 在输出里不可区分,这正是点名与伴生量存在的原因。
- `.yaml` 契约 MUST 被显式处置:两种语法各有一个抽取器(OpenAPI 取 `paths:` 下的方法键;结构化断言形取 `- id:`)。处置结果 MUST 使「已解析的 `.yaml` 文件数 + 被点名跳过的 `.yaml` 文件数 == 被扫描的 `.yaml` 文件总数」。

## 6. 本文档不拥有什么

- **计数**:逐形态的文件数与条款 id 数由对应 spec 的 `notes/clause-form-census.md` 拥有。
- **覆盖判定**:哪些条款未被认领、哪些 FR 未被引用,由核算脚本按本语法抽取后判定;本文档只给语法,不给结论。
- **条款内容**:任何一份既有契约的条款正文都 MUST NOT 被复制进本文档。本文档是语法的 owner,不是条款的副本;它与全仓契约的条款 id 交集里,任何 id 都不得以条款正文形式出现在这里(作为形态举例的引用除外)。
- **门控与预算**:本文档的措辞对既有门控扫描面零命中是落地前提,不是本文档定义的规则。
