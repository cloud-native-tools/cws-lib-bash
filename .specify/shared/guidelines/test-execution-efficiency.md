# 测试执行效率 (Test Execution Efficiency)

原则名 (principle title): **Efficient Test Execution (Concurrent by Default)**。文件路径:`.specify/shared/guidelines/test-execution-efficiency.md`。

本文件是**测试执行效率**纪律的唯一真源 (single source of truth)：它持有本纪律的全部判定内容——覆盖为何必要而不充分、效率何时成为质量属性、进程级并行与异步并发的**选择决策表**、并行合法的**隔离前置条件**、效率的测量口径，以及不可采纳的提速手段——这六项只在此定义，其余位置只承载指针。

其余位置只承载指针，MUST NOT 复制上列内容：constitution 模板与 live 宪法的原则条目、instructions 模板与 live 指令文件的常驻章节、生成 constitution 的 MUST-include 清单条目，全部以路径引用本文件。复制即第二定义点，二者会各自漂移——本纪律正是为消除这类「同一句话说两遍，两句都以为对方负责」的失效而存在。

**本纪律防的失效是「绿了但没人跑」**：测试存在、断言正确、覆盖率数字好看，但一次完整运行的耗时已超出开发者的容忍度，于是它被跳过、被 `-k` 缩窄、被 CI 之外的本地习惯性忽略——覆盖不再保护任何东西，而每个报告面仍然全绿。效率不是锦上添花的优化项，它是覆盖发生效力的前提条件。

## 覆盖为何是必要条件而非充分条件

覆盖回答的是「这条路径有没有被测到」，它不回答「这些测试会不会被执行」。两者是**独立失效**的：覆盖面可以在执行面归零之后保持不变——测试文件还在、断言还在、覆盖率报告仍可生成，只是没人跑它。

- **未执行的覆盖等于零覆盖**。一条只在理论上会被执行的测试，对缺陷的拦截能力与不存在的测试相同；差别只在于它让人误以为已被拦截。
- **执行成本是覆盖的乘数**：覆盖带来的保护 ≈ 覆盖到的路径 × 该覆盖被执行的频率。前者由测试内容决定，后者由执行成本决定；成本升高，频率下降，保护随之下降——而覆盖率这个指标对后者完全不敏感。
- **因此「补更多测试」不是本纪律的反面**，而是它的搭档：新增测试 MUST 同时回答它把一次完整运行推高了多少。只增加不加权的覆盖率是负资产——它提高了维护成本与执行时间，却不必然提高被执行的覆盖。

推论：任何以「覆盖已经够了」为由拒绝优化执行效率的判断，混淆了两个不同的量；任何以「效率优先」为由缩小 selection 的做法，则在减少被覆盖的路径。两者都不是本纪律允许的读法，正确的动作见下文两张表。

## 效率何时成为质量属性的判据

效率成为**质量属性**——即与正确性、覆盖率同层级、可被列为验收条件、可因不达标而拒绝交付——当且仅当下列任意一条成立：

- **饱和 (Saturation)**：一次完整运行的耗时已使它在声明的执行节奏中被跳过、缩窄或转由人工决定是否运行。判据不是绝对秒数，而是「它在应该运行的场合是否真的运行」。
- **乘数 (Multiplier)**：同一条命令在一次交付周期内被执行 N 次（本地改动循环、提交前、CI、收口比较），单次耗时按 N 放大。一次交付循环内的执行次数可由运行记录数出，不需要估算。
- **阻塞 (Blocking)**：该运行是某个流程门禁的前置条件，其耗时直接决定门禁的周转时间。

不满足以上任一条时，效率仍是优化项而非质量属性：可以改，但不得据以拒绝交付。**判据的取值来自测量，不来自印象**——"感觉有点慢"不是饱和，"上次完整运行被跳过了"是。

两个方向的红线：

- 不得把「更快」当作正确性的替代品：一次跑错的运行，零耗时也是零价值。
- 不得把「已达标」当作停止线：判据只决定此刻是否构成验收条件，不豁免下一节的选择程序。

## 选择决策表：进程级并行 / 异步并发 / 两者都不是

选择由**这条测试在等什么**决定，由该测试文件自身的判别属性读出，而不是由偏好决定：

| 判别属性 | 取值 | 选择 |
|---|---|---|
| 单条测试主要阻塞在**等外部事件**（网络、文件、数据库、进程输出） | 是 | **异步并发**（若测试框架与被测对象支持 async），否则按「进程级并行」处理 |
| 单条测试主要消耗**本进程 CPU**，或不适合改写为 async | 是 | **进程级并行** |
| **存在可独立重排的执行单元**（测试之间无顺序依赖），且任一单元可被安全地独立执行 | 是 | **并行可采纳**（进程级或异步，见上面两行） |
| 执行单元 MUST 按固定顺序、共享同一可变资源，或一次只能有一个实例 | 是 | **两者都不是**——保持串行，见下文 |

判别属性的读法：

- **异步并发**优化的是**等待**。它不增加 CPU 吞吐，只让同一进程在等 I/O 时去做别的事。对 CPU 密集的测试使用 async 只会让代码变复杂而墙钟不变。
- **进程级并行**优化的是**CPU 与子进程吞吐**。它让互相独立的执行单元在不同进程中同时跑。它对 I/O 等待也有效，但代价高（进程启动、内存放大、隔离要求）。
- **两者可以叠加**：一个套件的不同测试文件可以分别落入不同选择；不必为整个仓库选一种。但每个选择 MUST 能由该文件的判别属性复述，不得以「大家都这么跑」为由。

「两者都不是」是**合法结论**，不是失败：一个 3 秒的套件无需并行；一个必须独占某个外部端口的集成测试不能并行；一个被测对象本身是全局单例的测试在并行下只会变成不确定。此时正确的动作是串行执行并**记录理由**，而不是把并行强加上去再处理它制造出的失败。

## 并行合法的隔离前置条件

并行执行在下列每一条都成立时才是合法的；任一条不成立，并行本身就是缺陷来源，MUST 先修前置条件，MUST NOT 先开并行再把由此产生的失败当成「并行下的正常现象」：

1. **写入隔离**：任一条测试写的每一个路径，在并行执行下对其余执行单元不可见。临时目录 MUST 由框架按执行单元分配，MUST NOT 使用仓库内的固定路径、全局临时文件名或共享的 `basetemp` 子目录。
2. **状态隔离**：被测对象与其依赖的可变状态（全局变量、模块级缓存、单例、进程环境）MUST 在每次执行开始时处于确定初态。跨测试传递状态（「这个测试依赖上一个测试的副作用」）在并行下不是顺序问题，而是必然失败。
3. **无共享外部资源争用**：端口、具名 FIFO、锁文件、固定数据库名、远端配额等资源，MUST 要么按执行单元唯一分配，要么由该执行单元独占声明。争用表现为间歇性失败，而不是稳定失败——这正是它危险的地方。
4. **顺序无关**：任取执行单元的一个排列，结果集合 MUST 相同。顺序依赖在串行下被偶然掩盖，在并行下被随机暴露。
5. **失败可归名**：并行必须仍然产生可按名称比较的失败清单。若并行改变了失败报告的单位（例如把整批归并成一条），它就不再与串行可比，从而不再可用作判据——见下一节。

前置条件是否成立，由**实测差集**判定，不由阅读代码推断：同一棵树、同一 selection、同一命令跑串行与并行两遍，按名称比对两份失败清单。非空差集 MUST 被逐项处置为以下三者之一——(a) 修掉根因；(b) 为该测试声明**具名串行例外**；(c) 归入既存失败（其名称同时出现在两个清单中）。三类之外没有第四种处置。

**具名串行例外**的形态要求（本文件是这四条的唯一定义处）：

- **具名且可枚举**：例外是一个按名称可列出的标记，其全部成员 MUST 能由一次列出式收集命令枚举，成员数 MUST 能被记录。一个「关掉并行」的全局开关不是例外，是本纪律要防的静默降级。
- **理由须并行特有**：负载下的超时、共享状态、固定资源争用是可接受理由；「它偶尔红」不是。
- **一次运行仍是一次运行**：带例外的运行 MUST 合成为**一份**完整失败清单与**一个**退出码。排除项在一趟中补跑，两趟合成一份结果；补跑那趟若收集到零个测试，MUST 视为成功而非失败。
- **例外不得吞噬诊断**：标记只改变执行方式，MUST NOT 削弱该测试的断言、超时判据或失败可见性；标记的测试失败时 MUST 仍然使整体运行失败。

并行不得以**缩小选择范围**为代价：默认运行覆盖的测试集合 MUST 与串行运行相同。若某个选择范围（例如一类标记的测试）在并行下被默认排除，这已经是缩小 selection，不是并行。

## 测量的四个锚点

「更高效」是一个**同口径比较**结论，不是一个数字。一次合法的效率测量 MUST 同时固定四个锚点，缺任一项的结论不成立：

- **同一选择 (same selection)**：两次运行 MUST 覆盖同一个测试集合，且该集合 MUST 可枚举比对。缩小选择后测到的下降不是效率提升，是少跑了测试。
- **同一命令 (same command)**：两次运行 MUST 来自同一个命令入口，只在执行方式上不同。用两条不同的命令（不同的参数、不同的工作目录、不同的解释器解析路径）得到的耗时差不可归因于执行方式。
- **同一环境 (same environment)**：MUST 记录解释器、测试框架与其并行引擎版本、逻辑 CPU 数、调度模式，以及任何被清除的继承环境变量。未声明环境的耗时 MUST NOT 被用作比较依据。
- **名称级对照 (name-level comparison)**：正确性一侧 MUST 按**失败名称集合**比对，MUST NOT 只比对计数。计数相等可以掩盖成员变化：一条失败变绿、另一条变红，总数不变而结果已不同。MUST 双向记录——新增的失败名与消失的失败名——且消失项 MUST NOT 被追认为本次提速的修复。

耗时的取法：取自同一次运行自身报告的墙钟，MUST NOT 事后估算、MUST NOT 用计数或日志行数代理、MUST NOT 用一次重跑填补缺失的耗时数据。被判定的运行若被中断（某个执行单元被杀、进程组被中断、合成的某一趟未跑完），其耗时与失败清单 MUST NOT 被用作比较证据——不完整的运行不是一个取样点。

一次测量 SHOULD 只回答一个问题。同时衡量「并行是否更快」「并行是否等价」「调度策略是否更好」的单一运行，在任何一个维度出现异常时都无法定位，且违反了「一次执行只付一次成本、只产一份证据」的既有纪律。

## 不可采纳的提速手段

以下手段在任何情形下都**不是**让测试更快的合法方式，MUST NOT 出现在以效率为目标的变更中。它们都把「跑得更快」换成了「跑得更少」或「看不见变红」，而报告面全绿：

- **缩小选择范围**：用过滤条件、标记排除或去掉一整层测试来换取数字下降。合法的默认运行覆盖的集合由测试内容决定，不由耗时决定。
- **跳过 (skip)**：把慢的或并行下失败的测试标记为跳过。跳过的测试与不存在的测试等价，却继续计入覆盖率。
- **声明不稳定 (declare flaky)**：把间歇失败登记为「已知不稳定」并从判据中剔除。间歇失败是隔离前置条件不成立的证据，处置方式是修根因或声明具名例外，不是修改判据。
- **重跑到绿 (retry until green)**：用重试把偶发失败变成通过。「第二次过了」没有证明第一次为什么没过，只证明失败可以被隐藏；它同时污染了失败名称清单的可比性。
- **静默降级**：并行不可用时悄悄退回串行而不声明、不记录理由。降级本身是合法的，静默不是——一次运行 MUST 能被读出它实际走了哪条路径，以及为什么。
- **以「稍后再优化」关闭判据**：在效率已构成质量属性的场合（见上文判据）把问题移出验收范围。这既不更快，也不解决任何东西。

对称地，**为提速而改动被测对象的业务行为**同样不可采纳：执行效率是测试与运行器的属性，不是产品行为的属性。若一次提速要求放宽断言、改变被测代码的语义或减少检查，它已经越过了本纪律的边界，应按对被测对象的改动单独评审。

## 测量的取舍：一次执行，一份证据

固定四锚点与「一次执行只付一次成本」并不冲突：前者要求比较**可信**，后者要求比较**不昂贵**。两者的交汇形态是：

- 耗时与失败清单 MUST 在同一次运行中一次取全，落盘留痕，后续所有比较从留痕回答，MUST NOT 为找回已有数据而重跑。
- 需要多臂对照（例如两种调度策略）时，MUST 先问「这一对里已经有谁被排除」。若一条臂已经能证伪假设，第二条臂不是「更稳妥」，是未受约束的成本。
- 基线必须是一次**真实的、同口径的**运行，且在其取得后 MUST NOT 被重新取一次以匹配新结果——把基线移到结果旁边，比较的是树与它自己。

## 与相邻纪律的边界

本纪律与相邻纪律**相邻而不重叠**。

本纪律只规定测试**以什么代价执行**；「测试做什么、何时写、断言什么」归既有的测试相关原则，二者是分工而非重叠。每条边界按同一格式声明：对方拥有什么、本纪律拥有什么、本纪律 MUST NOT 重定义什么。

- **分工面（既有的测试相关原则）**：对方拥有覆盖率下限、测试何时先写、断言的粒度与命名。本纪律拥有执行方式、进程数、串行例外与隔离前置条件。MUST NOT 重定义对方的任何一条；同一条要求出现在两侧即为契约违反，按第一段的指针纪律修复（内容归回其 owner，另一侧改为路径引用）。
- **证据纪律**（`.specify/shared/guidelines/single-run-evidence.md`）：对方拥有一次昂贵执行的**输出是否被完整保全、是否被重复支付**；本纪律拥有**这份输出被用来比较什么**。两侧共用「同一次运行只付一次」的原则，但一次保全的证据可以被本纪律的四锚点判为不可比较（例如环境未声明），两者结论可以不同，那不是冲突。
- **单一真源**（`.specify/shared/guidelines/one-source-of-truth.md`）：对方拥有「为什么判据表与前置条件只能在一处定义」的论证；本纪律 MUST NOT 重定义「仅三种合法重复（机械复制 / 守卫副本 / 带日期记录）」。
- **临时目录纪律**（`.specify/shared/guidelines/temp-directory-discipline.md`）：对方拥有仓库内临时产物的落点与清理；本纪律只要求留痕落盘、可再寻址，MUST NOT 规定存放路径与命名。
- **快速失败**（`.specify/shared/guidelines/fast-fail.md`）：对方拥有并行下出现新失败时「该继续还是停下」的纠正 / 裁定二分；本纪律只规定处置的**类别**（修根因 / 具名例外 / 归入既存），MUST NOT 重定义分流判据。
- **机器与预算层**：哪一个命令被算作全量运行、一次流程能负担几次全量运行，归驱动侧的效率模型与预算台账；本文件只以路径引用，MUST NOT 复述其取值。

## 范围限制

本纪律是一份**写作与判断的规范**，不带机制：它 MUST NOT 被用来引入新的命令、技能入口、脚本、存储面或门禁，MUST NOT 建立测试耗时登记表、慢测试排行榜、覆盖率-耗时联表或任何持续测量设施。四个锚点描述的是**一次变更里如何比较**，不是一套常驻监控。执行效率的默认方式与参数取值归运行器自身，本文件不规定它们。

## 实证锚点（带日期记录，不作为现行事实引用）

2026-11-06，本仓库一次性测得：同一棵树、同一 selection、同一失败清单口径下，完整串行运行 1031.48 s、7475 通过 / 19 失败；默认并行运行 201.87 s、7474 通过 / 20 失败，加速比约 5.1×，失败名差集恰为一处（一个在并行负载下超过自身 60 s 超时、串行约 28 s 的自测）。这一组数字不构成本纪律的任何阈值——它是本文件「实测差集而非阅读代码推断」「名称级而非计数级比较」「具名串行例外而非跳过」三条的来历。仓库自那次起不再持有任何耗时承诺：后续每一次比较 MUST 自行取得同口径的两侧数据。
