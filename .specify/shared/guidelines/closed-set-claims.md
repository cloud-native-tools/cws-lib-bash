# 封闭清单声明 (Closed-Set Claims)

本文件是**封闭清单声明**纪律的唯一真源 (single source of truth)：声明的分类、构成要件、可判定判据、void 条件、回修程序与相邻 owner 的边界都只在此定义。指令模板 `.specify/templates/instructions-template.md` 的常驻顶级章节 `## Closed-Set Claims (封闭清单声明)` 只承载摘要 + 指针；分析侧落点 `.specify/skills/internal/analyze-artifacts/references/detection-and-severity.md` 与需求侧落点 `.specify/shared/guidelines/requirements-guidelines.md` 只以路径引用本文件，MUST NOT 复制其规则文本——复制即第二定义点，会各自漂移。

**本纪律防的失效是「不可判定的稳定性断言」**：规格写下「生成物内容不因本特性改变，差异仅限 (a)(b)」「未受影响的叶子 diff = 0」「除 X 外无任何文件变化」这类话，却既没有基线参照物，也没有把源改动的产物扇出算进去，还把一个未定义的聚合词当判据。它看起来像验收条件，实际无法机械执行：宽读成空集（全部豁免，检查变成橡皮图章），严读成必然误红；修复轮只能凭散文猜测，一轮补一处，越修越窄。

## 两类断言必须分开

- **确定性 (determinism)**：同一输入（树 + 配置）连续两次成功产出逐字节一致。参照物是它自己（run A / run B），不回答「变化是否在预期内」。
- **包含性 (containment)**：实现后的产物相对一个**已命名的基线状态**只在声明集合内变化。参照物是基线，不是上一轮自己。

两者 MUST 各自独立执行、独立声明。用 A/B 逐字节一致去证明包含性，或反过来，都属无效证据——两次运行可以「同样地错」。

## 一条可判定的包含性声明 MUST 具备五要件

1. **基线参照物**：点名基线的取得方式（提交号 / 工作树 / 在该状态捕获的产物清单），使比较有确定对象。没有参照物的「未受影响」是空话。
2. **比较单元**：按**产物类**声明比较口径（哪类文件、按字节还是按结构），并逐类执行。MUST NOT 用未定义的聚合词（「叶子」「其余文件」）充当比较单元。
3. **允许差异集的来源**：优先**机械导出**——把被编辑的源（模板、共享片段、生成器）经依赖关系映射到产物，取扇出闭包作为允许差异集；产物由共享源渲染时，MUST NOT 用手写的字节点清单（单个字段 / 单行）代替闭包。
   - 允许的手写形态：在**产物类**粒度列出允许变化的类别，**且**配一条漂移守卫——枚举真实扇出并断言与清单相等（例如「含某共享占位符的模板集合 = 声明的集合」）。这样清单是「被测试钉住的字面量」，不是复制。
4. **补集断言与结构不变量**：允许差异集**之外**的产物 MUST 与基线逐字节一致；集合**之内**的产物 MUST 通过结构不变量（语法检查、无未展开占位符、外部命令集为空或显式白名单、关键字段与顺序不变）。缺后半句，「允许全部脚本变化」就退化为橡皮图章。
5. **未定义聚合词清零**：「未受影响」「其余」「不变」等词 MUST 按要件 2 / 4 给出定义，或从声明中删除。MUST NOT 让未定义词承载验收语义。

## 判据

一条声明**可判定**，当且仅当：

1. 两个独立的复核者或程序依声明执行后得到同一 verdict；
2. 允许差异集可从仓库状态**重算**（被编辑的源 + 依赖映射），或被守卫测试钉住；
3. 声明同时给出「之外逐字节一致」与「之内结构不变量」两侧断言。

任一不满足即 **void**。

## 处置

- void 声明 MUST NOT 作为完成声明（SC / DoD / 验证任务）的依据；依赖它的阶段 MUST NOT 自称完成。
- 发现于分析期：按分析 owner 的严重度规则报告——若它承载 SC / DoD / 验证门，按「不可测的验收标准」判 **HIGH**；仅叙述性出现则受传播面 `none` 的 MEDIUM 上限约束。
- 修复属**文本级回修**（规格与判据），不需要改实现；修复后 MUST 重跑该门，而不是直接推进。
- 若「该声明到底该覆盖什么」需要**裁定**而非纠正，按 `.specify/shared/guidelines/fast-fail.md` 的二分判据停在异常点上报——本纪律不复述其分流规则。
- 发现于实现期且已据此产出证据：证据 MUST 标注 void 原因并按修正后的声明重取；MUST NOT 把旧证据折算为「部分达成」。

## 拒绝形态（命中即 void）

- 无基线参照物的稳定性断言；
- 用「叶子 / 其余 / 所有其他」等未定义聚合词承载比较；
- 对由共享源渲染的产物，按单个字段 / 单行手写允许差异；
- 产物类清单没有漂移守卫；
- 用 A/B 确定性证明包含性，或用包含性证明确定性；
- 「允许全部脚本变化」而不同时给出结构不变量。

## 与相邻 owner 的边界

- **派生而非复制**：允许差异集是「源改动 → 产物」的派生量，归 `.specify/shared/guidelines/one-source-of-truth.md` 的 owner / 引用纪律；本文件只规定它 MUST 被派生或被守卫钉住。
- **分析检测**：检测点归 `.specify/skills/internal/analyze-artifacts/references/detection-and-severity.md` 的 F 通道；本文件不定义分析流程。
- **需求写作**：需求侧指针归 `.specify/shared/guidelines/requirements-guidelines.md`；本文件不定义需求章节结构。
- **异常分流**：纠正 / 裁定二分归 `.specify/shared/guidelines/fast-fail.md`。

## 实证锚点（dated record，不作为现行事实引用）

2026-10-27，一个镜像工厂类客户端项目的规格把「生成物差异仅限 (a) 新增清单 / 差异输出、(b) TLS 长语法」写成封闭清单，而同特性编辑的共享 shell 片段被注入该仓库全部六类脚本模板，另新增一个生成物；同时 SC / DoD / 验证任务使用未定义的「未受影响叶子」。第一轮分析只抓到 TLS 一项遗漏，回修后第二轮分析又抓到扇出遗漏，判 HIGH——两轮成本来自同一根因：清单按字节点手写，而改动面按产物类扇出。本纪律的要件 3 / 5 即该判定的泛化。
