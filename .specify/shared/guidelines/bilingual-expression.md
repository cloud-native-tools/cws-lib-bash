# 双语表述(Bilingual Expression)

本文件是**双语表述(Bilingual Expression)** 约定的唯一 owner（[[STR-001]]）：**方向规则、唯一形态、覆盖定义面封闭集、豁免面封闭集、一致性规则、迁移边界**六组事实的唯一登记处。任何消费方（命令模板、技能、契约、测试、instructions、词汇表）MUST 以「路径 + 章节锚」引用本文件，MUST NOT 复述其方向、形态、覆盖面或豁免的枚举——复制即第二定义点，会各自漂移。

**seed 声明（F-01）**：requirements.md 的 FR-004/FR-007 枚举是封闭集初始内容（seed），封闭集的唯一 owner 归本文件；两处措辞以本文件为准，requirements 复写不构成分叉。

**Shared Strings 维护协议（C-03）**：`STR-001`/`STR-002`/`STR-003` 字面量的增改走需求阶段修订（Shared Strings 表归 requirements.md 属主）；各字面量的唯一消费点由契约测试的漂移守卫（`tests/contract/test_bilingual_expression.py`）核验，新增消费方 MUST 先改守卫白名单再落字。

**示范声明（C-02）**：本文件自身的定义行均按登记的逐字形态示范双语（声明：是）；读者可直接以本文件标题与章节标题为形态样例。

**Readers**: 框架维护者（编写与评审 `.specify/shared/`、`.specify/templates/` 文档的作者）、词汇表维护者、下游项目使用者——复用 `.specify/shared/guidelines/user-facing-comprehension.md` § 基准读者与覆盖协议 的全局基准读者，不新建第二套读者定义。
**Reading scenario**: 判断一处概念/流程的定义行是否必须双语、其形态（方向/括号宽度/紧贴/用词）是否合规时打开本文件核对对应章节，并据其决定提交或放行。

## 定义处与可判定信号

「定义处」的可判定信号清单封闭为 S1…S4；信号清单之外的新形态不在检查器判定范围，由评审面承担，本文件下次修订时补信号。

- **S1** 词汇表表体行：`.specify/glossary.md` 词条表的表体行（Canonical 登记处）。
- **S2** 覆盖定义面文档的章节标题行：覆盖面清单（见 § 覆盖定义面（封闭集））内文档的 `## ` 标题行。
- **S3** prose 中加粗引导定义行：`**<词条>**` 紧接半角括号/破折号/冒号的行。
- **S4** 文档主语言声明行与无声明时的保守缺省：声明优先；无声明时取正文 CJK/拉丁字母占比高者为主语言。

机械判定边界（C-012 的成文）：检查器只判定「含另一脚本括号段」的信号行——括号段内容以拉丁字母为主而词条以 CJK 为主（或反之）才构成双语形态尝试；纯同脚本括注（中文夹注、如「（封闭集）」）与 ID 引用括注（如「（F-01）」「（E2/E3）」）不在机械判定范围。S2/S3 信号行无此类括号段时，缺失判定不机械执行，由评审面承担；`missing-bilingual` 的机械落点是 S1 表体行中「含 CJK 却无任何括号形态」的 Canonical。

「首次定义」的语义判断**不属于任何可判定信号**（C-004）：检查器 MUST NOT 尝试判定一处提及是否首次定义，该面由评审承担；每一次提及也不要求双语（FR-002）。

范围声明（C-06）：本约定只约束 zh/en 主语言文档；其他主语言文档不在覆盖定义面封闭集内，不受本约定约束。

## 方向规则与唯一形态

### 方向规则

- 文档主语言为中文 ⇒ 形态逐字为「中文(English)」（[[STR-002]]）。
- 文档主语言为英文 ⇒ 形态逐字为「English(中文)」（[[STR-003]]）。
- 括号内一律为文档主语言的另一语言；同一文档以文档主语言决定括号语言。

方向判定层级（C-04/C-006）：文档头/frontmatter/首段的主语言声明优先（S4）；无法判定主语言时按保守缺省执行——段落级方向判定信号未登记，方向按文档级执行，无法判定时按段落各自语言执行方向规则，不强制统一。

### 唯一形态字面量条款

- 半角括号：括号宽度逐字为 `(` 与 `)`；全角 `（` `）` 紧贴词条即不合规。
- 紧贴：词条与左括号之间无空格，括号紧贴词条（`中文(English)` 形态内无任何空白）。
- 大小写逐字：词条大小写随登记形态逐字匹配，不自动归一（FR-005 的精确一致性自然覆盖大小写）。
- 不判翻译质量：括号内英文是否译得准不在本约定判定范围（显式排除项）。

形态判定正则（检查器唯一登记处，MUST NOT 在别处登记第二份）：

- 形态判定正则（检查器唯一登记行）：`[^\s()（）]+\([^()\n]+\)`；检查器 MUST 逐字读取本行登记的形态，语义不随实现漂移。

下列定义面 MUST 双语（信号见 § 定义处与可判定信号）；封闭集增删只能经本文件修订（FR-007 封闭集纪律），任何消费方 MUST 以「路径 + 章节锚」引用本文件，MUST NOT 复述本清单条目。

- 词汇表条目 Canonical：`.specify/glossary.md` 全部词条。
- `.specify/shared/definitions/` 概念条目。
- `.specify/shared/guidelines/` 与 `.specify/shared/workflow/` 文档的标题与定义行。

- instructions ambient 小节标题：`.specify/instructions.md` 的 `## ` 小节标题。
- `.specify/templates/` 章节标题。
- 命令与技能名首次定义处的承载文件。

清单本身之外的面不受约束；检查器 `coverage` 动作核验本清单每面存在且非空，整面缺失即 `coverage-missing`。

## 豁免面（封闭集）

下列内容豁免双语形态；封闭集增删只能经本文件修订。豁免不取消「首次定义处双语」（第三方专名条款除外）。

- 代码标识符：函数、变量、类名等源代码标识符。
- 路径：文件与目录路径。
- 命令字面量：shell 命令与 CLI 调用串。
- API 名：函数签名、端点、库接口名。
- YAML/JSON 键：结构化数据键名。
- 第三方专名：外部产品/项目/组织的名称。
- 公认缩写：如 SDD，在首次双语定义后可单语使用。

信号行命中豁免面（如自带括号的第三方专名）时的输出形态（C-05）：检查器报 warning 级 finding 并留评审裁定，不直接判红；评审记录归入 review 阶段产物。

- 约定只约束新写内容与本文件的维护；既有 dated records、已完成规格、历史记录不追溯重写（FR-006/FR-016）。

## 与相邻纪律的交界

- **jargon 白名单交界（FR-013/C-008）**：白名单术语的**提及处**维持可白名单状态，**定义处**仍须双语——两规则作用于不同面。白名单本身归 `.specify/shared/guidelines/user-facing-comprehension.md`，本文件 MUST NOT 成为其第二套规则真源。
- **One Source Of Truth 交界**：六组事实的唯一 owner 是本文件；ambient 小节、契约、测试只引用不复述。判据归 `.specify/shared/guidelines/one-source-of-truth.md`。
- **用户理解面**：基准读者复用 `.specify/shared/guidelines/user-facing-comprehension.md` 的全局基准，本文件不新建第二套。

## 检查器与守卫

机械守卫的入口是 `.specify/scripts/python/bilingual-expression-check.py`（已分发脚本，镜像于 `.specify/scripts/python/`）；**行为说明（入口/退出码/扫描规则/判定边界）见该脚本的 `--help` 与模块 docstring，本节只指针**。

- 能判（三类机械判定）：(a) 信号行是否含登记的半角紧贴双语形态；(b) 括号语言是否与文档主语言相反；(c) 覆盖定义面是否齐全。
- 不能判：语义——「括号内英文是否译得准」「这行是否在信号清单外仍是定义处」；检查器的绿是必要条件，MUST NOT 被援引为内容正确性证据（A7/C-012），最终验收归读者 oracle。
- 故障模式退出语义（C-07）：未知动作、缺失参数、路径不存在、文件不可读、owner 清单畸形、词汇表缺失——一律退出码 2 并输出错误说明，MUST NOT 静默跳过。
- review 面抽样消费检查器模块的 `sample_lines`（measurement.md C-004）：抽样选择由程序给出，评审 MUST NOT 自选。
